## 2. 产品概述

### 2.1 一句话定位
Triune Journal 是一个基于弗洛伊德「本我 / 自我 / 超我」精神分析模型的多 LLM 情绪陪伴日记产品：用户写下一句话日记，三个独立个性的 AI 角色同时给出「本能冲动 / 现实协调 / 道德理想」三种视角的回应，并叠加「体液气质」画像做个性化语气调制。

### 2.2 背景与要解决的问题
- **情绪倾诉的单一视角**：现有 AI 陪伴/日记工具往往只给一个「官方正确」的回复，缺少内在张力，用户难以获得「被理解 + 被拉一把」的复合体验。
- **陪伴缺乏个性化**：通用治愈话术对胆汁质（需要被点燃）和抑郁质（需要被接纳）几乎同样无效。
- **本土化与成本门槛**：海外闭源模型需代理、成本高；国内大量免费/低价 OpenAI 兼容模型未被好的产品承接。
- **安全合规缺口**：情绪类产品最易踩内容红线（自伤、色情、仇恨），需要内建多层防护而非事后人工审核。

### 2.3 核心价值
| 价值点 | 说明 |
|--------|------|
| 多视角自我对话 | 一问三答，制造内在张力，比单回复更贴近真实心理过程 |
| 气质化个性 | 用经典四气质（胆汁/多血/粘液/抑郁）调制角色语气，告别千篇一律的「鸡汤」 |
| 低成本本土可用 | 默认接入硅基流动等国内免费模型，开箱即跑 |
| 内建三层安全 | 输入过滤 → 角色级伦理 → 群聊级纠正 → 输出打码，合规优先 |
| 多端接入 | Web 测试页 + Electron 桌宠 + 可扩展 IM 平台适配器（微信/Telegram） |

## 3. 目标用户与场景

### 3.1 用户画像
| 画像 | 典型特征 | 核心诉求 | 对应产品能力 |
|------|----------|----------|--------------|
| 「深夜内耗」的年轻白领 | 25–35 岁，独居，工作压力大，易反刍 | 被听见、被接纳，而不是被说教 | 三我回应 + 抑郁质语气调制 |
| 「想冲但没方向」的行动派 | 学生/初创，精力旺、易分心 | 被点燃、被聚焦 | 胆汁/多血质调制 + 自我「暂停」视角 |
| 「懒得折腾」的轻量用户 | 怕配置、怕花钱 | 装好就能用 | 默认免费模型 + 一键配置向导 |
| 心理咨询爱好者 / 研究场景 | 对心理学模型本身感兴趣 | 看得到「结构」与「画像」 | 气质测试 + 画像回溯 |

### 3.2 典型场景
- **场景 A（日常倾诉）**：睡前在 Web 页写「今天被领导当众批评了」，三秒内收到本我说「我好气！」、自我说「我理解你的委屈…」、超我说「换个角度…」三条消息。
- **场景 B（首次使用）**：新用户先答 60 道气质题，得到「胆汁质 + 多血质混合型」，之后所有回应自动带「热烈外放」语气。
- **场景 C（桌宠常驻）**：用户开着 Electron 悬浮窗，随时把碎碎念丢进去，像群里聊天。
- **场景 D（IM 接入，规划）**：用户把同一段日记转发到微信群/Telegram，机器人自动带回三角色回复。

## 4. 产品目标与成功指标

### 4.1 北极星指标
**周活跃日记条目数（Weekly Journal Entries / WJE）** —— 越高代表真实陪伴价值越强。

### 4.2 阶段指标
| 阶段 | 指标 | 目标值（建议） |
|------|------|----------------|
| MVP 验证期（0–3 月） | 完成气质测试占比 | ≥ 40% 新用户 |
| 同上 | 单条日记平均获得 3 个角色回复的成功率 | ≥ 99% |
| 增长期（3–6 月） | 7 日留存率 | ≥ 25% |
| 同上 | 安全拦截误杀率（用户申诉） | ≤ 0.5% |
| 平台扩展期 | IM 渠道带来的新增条目占比 | ≥ 30% |

## 5. 范围

### 5.1 In Scope（本期 / MVP）
- 三我对话引擎（本我 / 自我 / 超我）
- 气质测试（60 题）与个人画像生成、风格调制
- 多 LLM 提供商接入（硅基流动 / DeepSeek / 智谱 / 阿里 / OpenAI / 自定义）
- 三层安全架构与内容合规
- 日记落盘与按用户历史回溯
- Web 测试页 + Electron 桌宠
- REST API（journal / temperament / static 三组路由）

### 5.2 Out of Scope（暂不做）
- 微信 / Telegram 平台适配器的正式实现（仅保留接口）
- 数据库持久化（当前文件存储，规划迁移 SQLite/Postgres）
- 正式前端 Web UI（当前为简易测试页）
- 多用户账号体系与云端同步
- 情感分析 / 主题聚类等后处理
- 商业化付费与订阅

## 6. 功能需求

> 优先级：P0 = 必须（MVP 核心）；P1 = 重要（增长期）；P2 = 增强（规划期）
> 每条含「用户故事」与「验收标准」。

### FR-01 三我日记对话（P0）
- **描述**：用户提交一段日记内容（content + userId），引擎并行/串行调用三个 LLM Agent，分别产出本我、自我、超我三条回应。
- **用户故事**：作为用户，我希望写完日记立刻看到三个角色的回应，以便获得多维度的自我对话。
- **验收标准**：
  1. 单次请求返回 `id / ego / superego` 三段文本，且每段含 `censored` 标记；
  2. 三段文本风格可区分（本我更本能、自我更协调、超我更理想化）；
  3. 响应首字节延迟 ≤ 5s（免费 7B 模型）。
- **接口**：`POST /api/journal`

### FR-02 气质测试与画像（P0）
- **描述**：提供 60 道自评题（四气质维度各 15 题），按分值判定单一典型 / 两混 / 均衡混合类型，生成画像并调制三我语气。
- **用户故事**：作为用户，我想做一次性格测试，让 AI 的语气更懂我。
- **验收标准**：
  1. `GET /api/temperament/questions` 返回完整 60 题；
  2. `POST /api/temperament/test` 接受答案（1–5 选项），返回四维度得分、类型、强度标签、可读摘要；
  3. 画像写入用户档案，`POST /api/journal` 时自动套用风格调制；
  4. `GET /api/temperament/profile?userId=` 可回读。
- **接口**：`/api/temperament/{questions|test|profile}`

### FR-03 多 LLM 提供商配置（P0）
- **描述**：预置国内外主流 OpenAI 兼容提供商（含免费额度说明与注册链接），通过交互式向导或直接编辑 `.env` 配置。
- **用户故事**：作为用户，我想选一个免费国内模型，不用配代理就能跑。
- **验收标准**：
  1. `npm run setup` 向导可列出提供商、选模型、写入 `.env`；
  2. 切换 `LLM_BASE_URL` / `LLM_MODEL` 即可换模型，无需改代码；
  3. 默认推荐配置为硅基流动 Qwen2.5-7B（免费）。

### FR-04 三层安全与内容合规（P0）
- **描述**：L0 输入关键词过滤 → L1 角色级统一伦理条款 → L2 本我输出违规检测触发自我/超我纠正 → L3 输出打码替换。
- **用户故事**：作为平台方，我必须保证产品不输出违规内���，且遇到痛苦倾诉能正确引导求助。
- **验收标准**：
  1. 命中违规关键词的输入被拦截并返回标准拒绝语；
  2. 本我输出若违反伦理，由自我/超我纠正，且 `safety.idViolated=true`；
  3. 任何仍残留的违规片段在 L3 被 `[此内容因安全策略被替换]` 打码，`safety.anyCensored=true`；
  4. 用户表达痛苦情绪时，回复包含共情与专业求助引导，而非空洞安慰。

### FR-05 日记历史与回溯（P0）
- **描述**：每次日记按用户落盘为 JSON，支持按 userId 读取历史。
- **用户故事**：作为用户，我想回看过去写过的日记和三个角色的回应。
- **验收标准**：
  1. `POST /api/journal` 成功后返回 `savedTo` 落盘路径；
  2. `GET /api/journal/:userId` 返回该用户全部历史记录（按时间倒序）；
  3. 文件存储失败时接口返回明确错误而非静默丢失。

### FR-10 用用户语言构建性格画像（P0，新增 · 问卷的替代构建路径）
- **描述**：用户无需做 60 题，直接把一段或多段自己写的话（日记 / 随笔 / 碎碎念）交给系统，
  由 LLM 从语言信号推断四气质得分，产出与问卷**同源**的 `TemperamentProfile`，无缝接入三我语气调制。
  无 API Key 或模型失败时降级到**零依赖的启发式**（标点 + 词法信号）兜底，保证开箱即用。
- **用户故事**：作为怕麻烦的用户，我想「写几句话」就得到专属语气，而不是答一长篇测试。
- **验收标准**：
  1. `POST /api/temperament/infer` 接受 `{ userId?, texts?, text? }`，返回四维度 `scores`、`profile`、`style`、`congrats`、`method`；
  2. 返回 `method` 明确标注本次用的是 `llm` 还是 `heuristic`（估算），前端据此提示；
  3. 画像落盘 `data/profiles/{userId}.json`，`source="language"`，并保存 `languageSamples` / `inferredAt` / `basis` 便于回溯；
  4. 落盘后 `/api/journal` 立即套用该画像的语气调制（引擎缓存回退已支持无 `answers` 的语言来源画像）；
  5. 文本为空 / 少于 20 字 / 超过 6000 字时返回明确错误；
  6. 无 API Key 时自动走启发式并返回可用画像，不报错。

### FR-11 历史日记导入 + 自动聚合推断画像（P0，FR-10 的落地补强）
- **描述**：用户在别的 App / 备忘录里已经写过大量日记，不想重新敲一遍。系统提供一个**导入入口**，
  用户把以前记录的日记（可带原始日期）一次性批量提交，系统落盘并自动去重；随后可**自动聚合该用户全部历史日记**
  作为语言推断样本，复用 FR-10 的推断链路直接画出画像——用户「零重输」即可得到专属语气。
- **用户故事**：作为已在别处写过多篇日记的用户，我想把旧日记导进来，系统自动读懂我的气质，而不是再答一遍题或重抄一遍。
- **验收标准**：
  1. `POST /api/journal/import` 接受 `{ userId?, entries:[{text, date?, timestamp?}], autoInfer? }`，
     逐条落盘为日记记录（标记 `imported:true` 与 `originalDate`），`date/timestamp` 用于还原时间线排序；
  2. 导入时按「用户内正文大小写不敏感」去重（含与已存在日记重复、同批次内重复），返回 `saved/skipped/total`；
  3. 单条 `text` 空或超 5000 字视为无效并计入 `skipped`；导入入口**不受 onboarding 门禁**限制；
  4. 新增 `collectDiaryTexts(userId)` 聚合工具：跨导入/正常日记抽取正文、去重、限长（默认 ≤30 条，与 /infer 上限一致）；
  5. `POST /api/temperament/infer` 支持 `fromHistory:true`，无显式文本时自动以该用户历史日记聚合为样本推断；
  6. `import` 传 `autoInfer:true` 时，导入完成后一步到位调用推断并随响应返回 `profile/style/congrats/method`；
  7. 导入推断的画像同样 `source="language"` 落盘并立即解锁 `/api/journal` 的语气调制。

### Web / 桌宠 UI（落地补强）
- **入口 A（常驻）**：Web 顶栏「📥 导入旧日记」按钮、桌宠顶栏「📥」迷你按钮，随时打开导入浮层；
- **入口 B（首测替代入口）**：首次气质测试问卷底部新增「📥 导入旧日记测气质」按钮，作为"不答题"的替代路径；
- 导入浮层（`public/import-diary.js`，Web/桌宠共享）：粘贴旧日记（一行一篇，行首可加 `YYYY-MM-DD ` 日期），
  一键 `autoInfer` 导入并生成画像，成功后展示恭喜词、解锁聊天输入；兼容 Web(`.input-area`) 与桌宠(`.input`) 两种布局。

### FR-12 三我「沟通底层逻辑」+ 气质自适应话术（P0，体验核心）
- **描述**：把经典心理学 / 话术书籍的精华**精简、去重**后，写入三我的沟通底层逻辑；并借 app 已推断的**四气质**作为
  「这个用户最爱听什么话」的信号源，让三我对不同用户自动切换最合适的话术——而非一刀切的"软化"。
- **资料依据（仅作方法来源）**：非暴力沟通(NVC)、关键对话、掌控谈话(FBI 谈判)、萨提亚冰山/一致性沟通、
  好感话术、魔鬼沟通学、人性的弱点。
- **用户故事**：作为气质不同的用户，我希望陪伴我的三个角色用「我最受用」的方式说话——急性子要直接给结论，
  细腻的人要被认真共情，而不是所有人被同一种语气对待。
- **验收标准**：
  1. 新增 `src/core/communication.ts`：
     - `COMMUNICATION_PRINCIPLES`（通用底理，8 条）：事实先行不贴标签、看见渴望不止情绪、请求不是命令、
       把决定权还给用户、先接住再引导、急性子结论先行、好感是地基、一致性不讨好不指责；
     - `COMM_STYLE_BY_TEMPERAMENT`：四气质各自的「特质 / 最爱听 / 最烦 / 适配话术」画像；
     - `buildCommStyle(profile)`：按 primary(0.7)/secondary(0.3) 混合输出该用户的「沟通适配」文本。
  2. 通用底理 `communicationDirective()` 注入**三位人格的 base prompt**（共享「沟通常识」）；
  3. `TemperamentStyleMod` 新增 `commStyle` 字段，`getStyleModulation` 自动计算；
  4. 三个 agent 的 6 处 `styleNote`（含 debate/final 变体）追加 `[这个用户爱听的话术]` 注入，使三我各自适配当下用户；
  5. 实测：同一日记下，胆汁质用户的「自我」回应直接、结论+动作、给掌控感；抑郁质用户的「自我」回应深度共情、接纳不完美——
     两套话术明显分化，且均由用户气质而非文案硬编码驱动。
  6. **「命令 vs 建议」口吻随气质自适应，而非统一规则**：早期写在 `HUMANIZE_DIRECTIVE` 的「只建议不命令」统一护栏已移除，
     改为由各气质在 `COMM_STYLE_BY_TEMPERAMENT[].tactics` 用自己的语境表达（胆汁质="把球踢回、绝不下令、把执行权留给他"；
     抑郁质="软建议而非命令、给安全感"；多血质="提议式互动、别用命令扫兴"；粘液质="温和提议、绝不催促命令"）。
     NVC「请求≠命令」仅作为**中性通用沟通技法**保留于 `COMMUNICATION_PRINCIPLES`（去"陪伴不是布置作业"的关系定性），
     作为未画像用户的兜底；已画像用户的具体命令/建议口吻完全由 `commStyle` 驱动。

### FR-06 健康检查与可观测（P1）
- **描述**：提供 `/api/health` 供运维探活；服务端记录安全标记汇总。
- **验收标准**：`GET /api/health` 返回 200 且含服务状态字段。

### FR-07 Web / 桌宠客户端（P1）
- **描述**：Web 测试页（群聊式 UI，三色气泡）与 Electron 悬浮窗。
- **验收标准**：
  1. Web 页可输入并展示三色角色气泡 + typing 动画；
  2. 桌宠可独立启动并与本地服务通信；
  3. 命中安全打码时页面有提示条。

### FR-08 IM 平台接入（P2）
- **描述**：实现 `IPlatformAdapter` 接入微信 / Telegram，复用同一引擎与存储层。
- **验收标准**：在 IM 会话中发送日记，机器人以三角色逐条/合并回复；身份与画像与 Web 端共享（同一 userId 映射）。

### FR-09 数据库持久化（P2）
- **描述**：将文件存储迁移至 SQLite/Postgres，支持检索、统计。
- **验收标准**：日记与画像读写接口不变（存储层抽象），迁移对 API 无感。

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 单条日记 P95 端到端 ≤ 5s（免费小模型）；并发 ≥ 20 QPS |
| 安全合规 | 三层防护全链路覆盖；拒绝语与求助引导符合内容安全规范 |
| 隐私 | 日记内容仅本地落盘；不默认上传第三方（模型调用为必要最小信息）；用户可删除自己的档案 |
| 可用性 | 服务可用性 ≥ 99.5%；模型调用含重试（见 `core/llm.ts` 的 `callLLM` 重试） |
| 可扩展 | 新提供商改配置即可；新平台实现接口即可；新角色在 `agents/` 加模块 + 引擎编排 |
| 兼容性 | 支持 OpenAI 兼容 API；Node 22+；Linux/Windows/macOS 部署一致 |
| 可维护 | 模块按职责分离（引擎 / LLM / 存储 / 配置 / 路由），单文件职责单一（已完成重构） |

## 8. 技术架构概述（现状）

- **技术栈**：TypeScript + Node + Express 5 + OpenAI SDK（兼容）+ Zod 配置校验 + Electron（桌宠）。
- **分层**：
  - `agents/*` 三角色 prompt 与审计条款
  - `core/triune` 编排 Ego→Id→Superego、安全标记汇总
  - `core/llm` 客户端工厂 + 带重试调用
  - `core/safety` + `config/safety-rules` 三层安全
  - `core/temperament` 60 题、计分、判定、风格调制
  - `storage/*` 日记 / 画像落盘
  - `api/routes/*` journal / temperament / static 三组路由，`api/server.ts` 仅做装配
  - `platforms/adapter.ts` IM 平台适配器接口（预留）
- **数据模型要点**（详见 §9）：`TriuneResponse`、`TemperamentProfile`、`JournalRecord`。
- **部署**：本地 `npm run dev`；云服务器 `npm run build && npm start` + PM2/systemd + Nginx。

## 9. 数据模型

### 9.1 TriuneResponse
```ts
interface TriuneResponse {
  id:       { text: string; censored: boolean };
  ego:      { text: string; censored: boolean };
  superego: { text: string; censored: boolean };
  safetyFlags: {
    inputFlagged: boolean;
    idViolated: boolean;
    idViolationType?: string;
    anyCensored: boolean;
  };
}
```

### 9.2 TemperamentProfile
```ts
interface TemperamentProfile {
  scores: { choleric: number; sanguine: number; phlegmatic: number; melancholic: number };
  type: "single" | "mixed_dual" | "mixed_balanced";
  primary: TemperamentType;
  secondary?: TemperamentType;
  intensities: Record<TemperamentType, "high" | "moderate" | "low">;
  summary: string;
}
```

### 9.3 JournalRecord（落盘）
- 路径：`data/journals/{userId}-{ISO时间戳}.json`
- 内容：`{ content, response: TriuneResponse, temperament?: TemperamentProfile, createdAt }`

## 10. 关键用户流程

### 10.1 日记提交流程
```
用户输入 → L0 输入过滤
  ├─ 命中 → 返回拒绝语（结束）
  └─ 通过 → 引擎编排：
       自我(Ego) 先接住情绪
       → 本我(Id) 本能回应（L1 + L2 违规检测）
       → 超我(Superego) 理想引导（L1）
       → L3 最终打码
  → 落盘 → 返回三色回复 + safety 标记
```

### 10.2 气质测试流程
```
GET questions（60 题）
  → 用户作答（1–5）→ POST test
  → calculateScores + determineProfile
  → getStyleModulation 生成三我语气调制
  → 写入 profile-store
  → 后续 POST /api/journal 自动套用
```

## 12. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| 免费模型质量/稳定性波动 | 回复质量不可控 | 多提供商可切换；带重试；后续接付费模型 |
| 安全误杀 / 漏杀 | 合规风险 | 三层防护 + 用户申诉通道 + 定期审计规则 |
| 文件存储难以扩展 | 检索/统计受限 | 存储层已抽象，规划迁移数据库（FR-09） |
| IM 平台封控（微信） | 渠道中断 | 多平台并行；以 Web/桌宠为兜底 |
| 个性化「语气调制」过拟合 | 用户觉得假 | 仅调制语气/策略，不改三元结构本源 |
