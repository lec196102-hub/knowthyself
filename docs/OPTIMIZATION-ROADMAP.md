## 1. 设计原则（后续所有改动遵循）

1. **单点变更**：换存储引擎只动 `storage/adapter.ts`；换模型只动 `llm/client.ts`；加平台只实现 `platforms/adapter.ts` 接口。
2. **行为不变优先**：重构用"抽实现 + 门面再导出"，保证已有 `import` 路径与对外签名稳定。
3. **零额外依赖优先**：测试用 `node:test`，样式用纯 CSS，避免为小需求引入重型库。
4. **桌宠体验标准**：双击即用、登录自启、托盘常驻、情绪可视、动效克制不吵。

## 2. 里程碑规划

### M1 · 体验打磨（前端 / 动效 / 主题）— 高优先级
目标：达到成熟桌宠 App 的视觉与手感。

- [ ] **主题系统**：用 CSS 变量统一色彩（`--bg / --mood-id / --mood-ego / --mood-superego / --text`），先补一套浅色主题，按系统 `prefers-color-scheme` 或记忆的设置切换；设置项落 `localStorage`。
- [ ] **个性化舞台升级**：在现有"图片上传"基础上，支持可选 SVG/动态形象皮肤（`data-mood` 驱动表情切换），提供 2~3 套形象皮肤；保留"无图即纯聊天"的极简默认。
- [ ] **消息动效与可读性**：长文自动折叠（"展开全文"）；引用用户原话时高亮；代码/链接特殊渲染；对方"正在说"用气泡打字机效果。
- [ ] **无障碍**：`prefers-reduced-motion` 关闭呼吸/抖动；`aria-live` 播报新消息；输入框焦点环可见。
- [ ] **移动端网页**：`index.html` 增加响应式断点，手机浏览器也能舒服用（桌宠形态保留在 Electron）。
- 验收：浅/深主题切换无错位；动效在低配机不卡；reduced-motion 下静止。

### M2 · 便捷分发（打包 / 自动更新 / 一键配置）— 高优先级
目标：用户"下载 → 双击 → 开聊"，无需命令行。

- [ ] **签名安装包**：`electron-builder` 接代码签名（Windows 用 EV 证书 / macOS 用 Developer ID），消除"未知发布者"警告；NSIS 安装向导含"开机自启"勾选。
- [ ] **自动更新**：接入 `electron-updater`，`package.json` 增加 `publish` 配置；后端版本接口 `/api/version` 供前端提示更新。
- [ ] **一键初始化向导**：首次启动 `setup` 流程做成网页向导（选模型/填 Key/测连通），替代纯命令行 `npm run setup`；Key 存系统钥匙串而非明文 `.env`。
- [ ] **生产态后端稳定**：内置 `dist` 服务进程管理（崩溃自拉起、单例锁避免重复监听）；日志落文件（`logs/`），便于排查。
- 验收：干净机器双击安装包即可聊天；断网/无 Key 时有明确引导而非白屏。

### M3 · 数据层升级（数据库）— 中优先级
目标：海量日记/记忆检索更快、更稳。

- [ ] **抽象落地**：当前所有读写已集中在 `storage/adapter.ts`，新增 `SqliteAdapter` 实现同一接口（`ensureDir/readJsonFile/writeJsonFile/listFiles/deleteFile` 的等价语义改为 `query/exec`），`config.ts` 用 `STORAGE_DRIVER` 切换，**其余业务代码零改动**。
- [ ] **选型**：本地优先 SQLite（`better-sqlite3`，同步 API、零运维）；多设备同步可后续接 Postgres/云。
- [ ] **迁移脚本**：`scripts/migrate-json-to-sqlite.ts`，读旧 `data/*.json` 写库，幂等可重跑；保留 `data/` 备份。
- [ ] **索引**：日记按日期/用户/关键词建索引；记忆与知识库做向量检索（可选，配合 RAG）。
- 验收：切 SQLite 后单测与干测仍全绿；旧数据迁移完整无丢失。

### M4 · 平台扩展（适配器）— 中优先级
目标：不止桌宠，还能在常用IM里陪你。

- [ ] **实现 `platforms/adapter.ts` 的具体适配器**：微信(个人号/企业微信)、Discord、Telegram、飞书，统一收消息 → `processDiary` → 回消息。
- [ ] **会话上下文桥接**：把各平台会话映射为 Triune 的"用户/会话"标识，复用记忆与气质画像。
- [ ] **权限与节流**：平台 Rate Limit、敏感词二次确认、撤回/编辑同步。
- 验收：同一套引擎在 ≥2 个平台跑通端到端对话。

### M5 · 可观测性与安全 — 中优先级
目标：出问题时能定位，敏感数据有边界。

- [ ] **结构化日志**：`shared/logger.ts` 已是分级接口，后续可无缝替换为 `pino`，输出 JSON + 文件轮转；关键路径打 `traceId`。
- [ ] **健康检查增强**：`/api/health` 返回模型连通、存储驱动、版本；前端横幅展示更细。
- [ ] **安全审计**：L0~L3 四层过滤补单测覆盖边界（提示注入、越权访问、PII 泄露）；Key 不进日志；`.env` 不入库。
- [ ] **隐私开关**：用户可一键导出/清除所有本地数据；记忆保留策略可配置（按天数/条数）。
- 验收：生产日志可追责；安全单测覆盖新增拦截规则。

### M6 · 工程化（CI / 测试 / 文档）— 低优先级（持续）
- [ ] **CI**：GitHub Actions 跑 `tsc --noEmit` + `node --test tests/unit/*.test.ts` + `tsx tests/test-dry.ts`，PR 必过。
- [ ] **覆盖率**：`c8` 统计单测覆盖，门禁 ≥ 当前基线。
- [ ] **E2E**：用 Playwright 跑 `widget.html` 冒烟（发消息→看到三我→自我拍板）。
- [ ] **文档**：`README` 补"快速开始/打包/二次开发"；架构图随模块变更同步更新。
- 验收：每次 push 自动质量门禁；新人不读源码也能上手。

## 3. 风险与回滚

| 改动 | 主要风险 | 回滚方式 |
|------|----------|----------|
| 主题系统 | CSS 变量遗漏导致某组件 invisible | 保留默认深色，主题=叠加层，关掉即回退 |
| 数据库迁移 | 数据丢失/格式不兼容 | `data/` 先备份；迁移脚本幂等可重跑；保留 JSON 适配器 |
| 生产内置后端 | 端口冲突/进程管理复杂 | `isPortOpen` 探测 + 单例锁；失败回退"提示手动 `npm run dev`" |
| 平台适配器 | 平台 API 限流/封号 | 默认关闭，需显式开启；严格节流与人工确认 |

通用原则：每个里程碑独立分支、独立评审、可单独回滚；破坏性改动必须保留旧路径至少一个大版本。

## 4. 建议执行顺序（性价比）

1. **M1（主题 + 形象皮肤）** → 立刻提升"像成熟桌宠"的体感，纯前端零风险。
2. **M2（签名安装包 + 一键向导）** → 决定能否真正"发给朋友用"。
3. **M3（SQLite）** → 数据量大了再做，接口已留好。
4. **M4 → M5 → M6** → 按实际需求与资源推进。
